About this project

Small X Studio runs small AI models entirely in your browser. Every image and summary is computed on your own device with ONNX Runtime Web; the site only supplies the files.

How it works

  1. The first time you use a tool, your browser downloads that tool’s model from this site and stores it with the Cache API. Later visits load it from disk, so only the first run waits for the network. Each tool downloads only the model you pick.
  2. ONNX Runtime Web turns the model into a session on your GPU (WebGPU or WebNN) or CPU (WebAssembly, multi-threaded) and runs it. Your prompt or text is processed locally and never sent anywhere.
  3. The result appears on the page. Images and summaries are kept only in the open tab: download or copy what you want to keep before you reload or leave.

Each model has its own pipeline in plain JavaScript: the tokenizers (CLIP and GPT-2 byte-level BPE, and a word table for pixel art), the samplers (DPM-Solver++ for Small SD, flow matching for pixel art), and beam search for summaries, with the summarization model’s own settings (4 beams, no repeated 3-word phrases, length penalty).

Choosing a processor and model

  • Small SD is fastest on WebGPU: seconds per image. WebNN compiles the model again for each new image size, so the first image at a size is slow. The CPU takes minutes per image and is limited to 512×512, since larger images don’t fit in WebAssembly’s 4 GB memory. The page shows a time estimate for the CPU and refines it from your device’s first CPU image.
  • Switching Small SD between a GPU processor and the CPU needs a page reload: ONNX Runtime decides once per page whether CPU work runs in a background worker. The reload clears the images made so far.
  • Mini Pixel Art uses WebGPU when that’s your processor, and the CPU otherwise. At 8.8M parameters it’s small enough for either: well under a second per sprite on WebGPU, several seconds on the CPU. Captions are looked up word by word in the training vocabulary, so write short noun phrases (“side-view knight with sword”); unknown words are ignored and listed after each run.
  • Summaries always run on the CPU, in a background thread, because the Fast model’s int8 weights only run well on WebAssembly. Fast and Best summarize at about the same speed once loaded; Best takes about twice as long to load and uses more memory. The model was trained on news, so it works best on factual English prose. It reads up to 1,024 tokens (about 750 words) at a time: longer text is split at sentence ends, with one summary paragraph per part.
  • Seeds make images reproducible: the same seed, prompt and settings give the same image. “Reuse seed” on any image puts its seed back in the form.

Prompts, text and results are never sent to the site. Apart from downloading files, the only request the pages make is a status check that asks whether the model files are available.

Storage

The models this browser has stored for the site. Deleting one frees its disk space; it downloads again the next time you use its tool. A tab that already has a model loaded keeps using it until that tab is reloaded.

Checking…

Deletes all stored models and resets your settings (processor, chosen models, measured CPU speed).

What your browser needs

  • WebGPU with 16-bit float support (shader-f16) for the fastest image generation, in a recent Chrome or Edge; or WebNN (experimental) on Windows. The image page checks your device and shows which processors are available, and why not if one isn’t.
  • WebAssembly with threads for everything on the CPU, including summaries. Threads need SharedArrayBuffer, which browsers only allow on cross-origin isolated pages; this site is set up for it.
  • A secure address: https:// or localhost. Browsers turn WebGPU off on plain HTTP, so if the GPU shows as unavailable, check the address bar.
  • Disk space for the models you use, and about 4 GB of free memory for Small SD.

Source code

Small X Studio is open source: github.com/xavier-hernandez/small-x-studio. Bug reports and suggestions are welcome there.

Built with

  • ONNX Runtime Web 1.29, served by this site (no CDN). It is the only JavaScript library.
  • Plain HTML, CSS and ES modules, with no build step. A small ASP.NET Core server hosts the files and answers the status check.
